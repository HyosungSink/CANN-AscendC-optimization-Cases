## Description

This PR adds the `sparse_attn_sharedkv` AscendC kernel and aligns its public API with the upstream implementation.

### Changes

- Add FP16/BF16 sparse shared-KV attention kernel and host-side tiling logic.
- Support SWA, CFA, and SCFA dispatch modes.
- Add NPU Graph capture/replay support using a device-resident tiling cache.
- Align the PyTorch API defaults and keyword-only arguments with upstream.
- Derive KV page strides internally instead of exposing them through the public API.
- Extend `ge_helper` with float/bool attributes and fix tensor descriptor indexing.
- Add FP16, BF16, NPU Graph, and public API schema tests.

### Tiling cache design

The standalone `ge_helper` launch path computes tiling on the host, while NPU Graph replay requires the captured device tiling address to remain stable. This PR therefore adds a reusable `TilingTensorCache<T>` adaptor in `csrc/utils/ge_helper.h`.

- This is a **device-address cache**, not a Host Tiling result cache. Parser/Checker/`DoOpTiling` still run for each eager wrapper invocation and once during graph capture; the serialized, deterministically initialized `TilingData` bytes are used to find a persistent device slot.
- Cache state is isolated by the device of the current NPU stream, guarded by a mutex, and limited to 512 persistent entries per `TilingData` type and device. Existing slots are never evicted or overwritten because captured graphs may retain their addresses.
- An eager cache miss allocates/populates a stable slot and performs the H2D copy. During capture, only a cache hit is allowed; a cold or mismatched configuration fails with an actionable eager-warmup message.
- When all 512 persistent slots are occupied, an eager miss uses a one-shot tiling tensor instead of growing persistent memory. A capture miss still fails because that address is not graph-stable.
- Warmup is needed to initialize the stable device slot before capture, not because Host Tiling is illegal during capture. Replay executes neither the Python/C++ wrapper nor Host Tiling; it reuses the captured kernel launch and tiling address.

The NPU Graph test performs eager warmup, captures once, then replays with changed input contents and compares each result against a fresh FP32 reference. A cold-capture path is expected to fail rather than allocate or copy new persistent tiling data inside capture.

### Notes

- Currently supports `BSND`/`TND` query layouts and the `PA_ND` KV layout.
- `metadata` must be provided externally as an `int32[1024]` tensor.
- `return_softmax_lse=True` is not supported yet.
