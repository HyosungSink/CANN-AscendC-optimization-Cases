
### What does this PR do, and why?

The Qwen GDN path rearranges token-major mixed QKV into contiguous Q, K, and V buffers, then computes GDN gating separately. On Ascend A2/A3 this produces multiple copy/concat launches followed by a gating launch, even though the two pieces of work are independent.

This PR adds **one** custom operator, `npu_fused_rearrange_mix_qkv_gdn_gating`. Its `MIX_AIC_1_2` kernel runs QKV DMA on AIC and GDN gating on AIV in the same launch. It returns packed QKV, FP32 `g`, and BF16 `beta`. The operator supports the model's actual mixed head parameter types (`A_log` FP32 and `dt_bias` BF16) as well as matching FP32/BF16/FP16 head parameter types. Gating nonlinearities compute in FP32, as in the existing Triton implementation; this conversion occurs inside the kernel, without an additional device launch or intermediate GM tensor.

`A2A3DeviceAdaptor` dispatches to the fused operator. Other device families retain the existing split path. A batch containing both speculative and non-speculative QKV inputs also retains the split path because neither input contains all of the gating rows. The operator has PrivateUse1 and Meta registrations, handles zero tokens, and validates its direct-call input contract at the C++ boundary. This PR does **not** add or depend on a standalone `rearrange_qkv_dma` operator.

### User-facing change

No public API or configuration change. Eligible A2/A3 GDN calls use the fused operator automatically; other device families and mixed speculative batches retain their existing behavior.

### End-to-end serving performance

Qwen3.6-27B, TP=2, FULL_AND_DECODE enabled; prompt length 1024, generation length 512, maximum request concurrency 8, 128 requests. The table compares the reported median benchmark runs. Both variants completed all 128 requests with zero failures; each generated 65,536 output tokens from 132,393 input tokens.

| Metric | Before | After | Change |
| --- | ---: | ---: | ---: |
| Output throughput (tok/s) | 191.07 | 197.10 | +3.16% |
| Total token throughput (tok/s) | 577.05 | 595.28 | +3.16% |
| Median TPOT (ms) | 38.34 | 37.06 | −3.34% |
| Median end-to-end latency (ms) | 21,434.25 | 20,779.10 | −3.06% |
| Median TTFT (ms) | 1,842.71 | 1,837.10 | −0.30% |
| Benchmark duration (s) | 343.00 | 332.50 | −3.06% |

The improvement is concentrated in generation latency; TTFT is nearly unchanged. These are serving-level results, not an operator-only speedup.

### Operator-level microbenchmark

The benchmark compares the installed vLLM `rearrange_mixed_qkv` plus `DeviceOperator.fused_gdn_gating` split path against the new fused operator. Synthetic inputs match the observed Qwen3.6-27B TP=2 per-rank call: Q/K/V dimensions 1024/1024/3072, 24 heads, BF16 mixed QKV/a/b/`dt_bias`, and FP32 `A_log`. Outputs are checked before timing. Results are in µs per invocation; speedup is split latency divided by fused latency. Eager uses host wall time with NPU synchronization; graph uses NPU events around replay. These are operator-path measurements, not model-level throughput.

The following results are reported for the current single-operator patch based on `44f9bf53d93fe6a5b1362b7d81a050d3b0cd997d`, not the earlier DMA-plus-fusion prototype.

#### Python unit tests — all passed

```bash
python -m pytest -q tests/ut/ops/test_fused_rearrange_mix_qkv_gdn_gating.py
```

The file contains two tests: supported A2/A3 adaptor dispatch with the real mixed parameter dtypes, and split-path fallback when the device adaptor has no fused implementation. Both passed according to the reported test run.

#### NPU operator/end-to-end tests — all passed

```bash
python -m pytest -q \
  tests/e2e/nightly/single_node/ops/singlecard_ops/test_fused_rearrange_mix_qkv_gdn_gating.py
```

The file defines 81 parameterized cases in total:

- 72 numerical-reference cases across three Q/K/V layouts, six token counts (including zero), and four `A_log`/`dt_bias` dtype pairs, including the model's FP32/BF16 pair;
- three non-default-stream and NPU graph replay cases;
- one model-dispatch case, four invalid-direct-input rejection cases, and one Meta shape/dtype case.

All cases passed according to the reported test run. The 128-request Qwen3.6-27B serving A/B test above is the additional model-level end-to-end validation (zero failed requests in either variant).
